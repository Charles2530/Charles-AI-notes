# 具身智能从零路线来源台账

这份台账服务于 `files/embodied-ai/beginner-learning-path.md`。正文定位为入口文章，不做机器人学习论文综述，而是帮助读者先建立闭环系统视角：传感器、状态、动作、控制、数据、评测、安全和世界模型如何接在一起。

## 资料取舍

| 主题 | 主要来源 | 在正文中的用法 |
| --- | --- | --- |
| 真实机器人 Transformer policy | [RT-1](https://arxiv.org/abs/2212.06817) | 支撑“VLA 不是纯语言理解，而是图像、指令、历史动作和动作空间的闭环策略”。 |
| VLM 知识迁移到动作 | [RT-2](https://arxiv.org/abs/2307.15818) | 支撑“web-scale VLM 可以增强语义泛化，但仍受机器人动作接口和数据约束”。 |
| 跨机器人数据 | [Open X-Embodiment](https://arxiv.org/abs/2310.08864) | 支撑“跨机器人数据的关键在标准化观测、动作、任务和评测格式”。 |
| 开源 VLA | [OpenVLA](https://arxiv.org/abs/2406.09246) | 支撑“VLA 已进入可复现、可微调和可部署阶段，但仍依赖数据格式、动作解码和评测”。 |
| Action chunk | [Learning Fine-Grained Bimanual Manipulation with Low-Cost Hardware](https://arxiv.org/abs/2304.13705) | 支撑 ACT、action chunk、低成本双臂模仿学习的写法。 |
| 动作轨迹扩散 | [Diffusion Policy](https://arxiv.org/abs/2303.04137) | 支撑“动作表示可以是条件扩散生成，并适合多峰、高维动作分布”。 |
| Affordance 约束 | [SayCan](https://arxiv.org/abs/2204.01691) | 支撑“语言上合理的动作必须被机器人当前可执行性约束”。 |
| 仿真与双臂 benchmark | [RoboTwin](https://arxiv.org/abs/2409.02920) | 支撑仿真 benchmark、数字孪生和双臂任务评测的边界。 |

## 写作边界

正文没有把具身智能简化成 VLA，因为 VLA 只覆盖任务理解到动作输出的一段。传感器标定、动作空间、控制频率、低层控制器、失败恢复和安全停机同样决定系统能不能部署。

正文也没有把仿真写成真实数据的替代品。仿真更适合便宜覆盖场景、做失败回放和评测，但训练收益必须经过 sim-to-real 校验；不同任务关心的 gap 不同，视觉任务、抓取任务和导航任务不能用同一个“逼真度”指标概括。

正文避免使用单一成功率评价具身系统。正文强调阶段成功率、失败桶、near-failure、碰撞、人工介入、恢复次数和长时状态漂移，因为这些指标更接近部署风险。

## 核对口径

正文里的“闭环”指持续观测、判断后果并修正动作，不是只让模型连续输出动作。RT-1 和 RT-2 作为 VLA 入口使用；Open X-Embodiment 和 OpenVLA 作为数据与可复现入口使用；ACT 和 Diffusion Policy 作为动作表示入口使用；SayCan 作为语义规划受 affordance 约束的入口使用；RoboTwin 作为仿真和 benchmark 入口使用。

没有在正文里列最新 VLA 模型排行榜。排行榜信息变化快，而且这篇文章的目标不是追逐最新模型，而是让读者能判断新模型到底改了传感器、动作、数据、策略、仿真还是评测中的哪一层。

## 图片使用口径

正文保留三张图。RT-1 图用于说明真实机器人 policy 的输入输出链路：图像和语言只是条件，模型最终必须落到机器人动作空间。RT-2 图用于说明 web-scale VLM 知识迁移到动作 token 的路线：语义能力提升后，动作接口和机器人数据仍然是约束。Open X-Embodiment 图用于说明跨机器人数据的规模和多样性，但正文刻意把重点放在观测、动作、任务和评测接口，而不是只强调数据量。

没有额外引入 ACT、Diffusion Policy、SayCan 或 RoboTwin 的图片，因为这篇文章的视觉负担已经够重；这些论文在正文中作为概念支撑和外部精读入口出现。后续如果单独重写动作表示、闭环恢复或 Sim2Real 页面，再把对应图放进专页更合适。

## 事实分层

正文把事实分成三层。第一层是论文明确提出的模型或数据路线，例如 RT-1 的真实机器人 Transformer policy、RT-2 的 VLA、Open X-Embodiment 的跨机器人数据、ACT 的 action chunk、Diffusion Policy 的动作轨迹建模。第二层是从这些路线推出的工程边界，例如不能把 VLA 等同于完整机器人系统，不能把仿真结果直接外推到真实部署。第三层是站点自己的教学组织，例如先从抓杯子理解闭环，再按传感器、动作、VLA、数据、评测、世界模型逐层学习。

如果后续加入更新的机器人基础模型，正文应优先判断它属于哪一层改动：新的视觉表征、新的动作接口、新的数据混合、新的仿真平台、新的评测协议，还是新的闭环恢复机制。只有这样，正文才不会变成模型清单。

## 未采用的写法

- 没有把“机器人 + 大模型”当作定义，因为这会遮住控制和安全问题。
- 没有把跨机器人数据规模当成唯一卖点，因为接口标准化和评测口径同样关键。
- 没有把世界模型描述成“生成未来视频”就足够，因为机器人需要的是动作条件化后果、风险检查和闭环收益。
- 没有把仿真结果直接外推到真实部署，因为接触、摩擦、传感器噪声和执行器延迟会改变策略表现。
