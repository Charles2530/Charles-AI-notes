# 长视频怎样连续生成

一段固定长度的视频可以从整块噪声出发，反复更新所有帧，最后一起解码。播放者若要在第一小段完成后就看到画面，模型就必须在未来尚未生成时确定当前内容。此后生成的片段还要接住已经播放过的动作、外观和镜头，不能回头修改它们。

这改变了生成顺序，也改变了训练时应当让模型看见的上下文。仅仅把一次调用的帧数调大，无法得到同样的能力。下面沿着一段视频的生成过程，解释块内去噪、块间自回归、训练分布和缓存怎样配合。固定长度视频的完整数据流见[视频生成主文](video-and-multimodal-diffusion.md)。

## 视频时间和去噪时间分别向哪里走

先把经过 VAE 压缩的视频写成 \(K\) 个连续块 \(z^{(1)},\ldots,z^{(K)}\)。一个块可以包含多个 latent 帧，每帧又包含许多空间 token。这里的 \(k\) 表示视频中的先后位置，\(\tau\) 表示加噪程度。本文约定 \(\tau=1\) 为纯噪声端，\(\tau=0\) 为干净 latent 端。

固定长度的联合去噪可以让所有块共用同一个 \(\tau\)，从 \((1,1,1,1)\) 一起走到 \((0,0,0,0)\)。如果网络使用双向时空注意力，第一个块在去噪时能读取第四个块的当前状态，第四个块也能读取第一个块。整段动作可以共同调整，但第一块尚未最终确定时，后面的计算已经发生。

严格按块自回归则先完成第一个块，再生成第二个块。它对应条件分布分解

\[
p_\theta(z^{(1)},\ldots,z^{(K)}\mid c)
=\prod_{k=1}^{K}p_\theta(z^{(k)}\mid z^{(<k)},c),
\]

其中 \(c\) 是文本等外部条件。每个条件分布内部仍可使用扩散或 Flow Matching，从一块随机噪声逐步生成当前块。概率分解本身来自链式法则，实际模型还要通过结构和训练学会这些条件分布。

用四块视频表示两条时间轴，可以看到区别。

| 已进行的生成工作 | 第一块的噪声量 | 第二块 | 第三块 | 第四块 |
| --- | --- | --- | --- | --- |
| 开始生成第一块 | 1 | 未创建 | 未创建 | 未创建 |
| 第一块去噪到中途 | 0.5 | 未创建 | 未创建 | 未创建 |
| 第一块完成，开始第二块 | 0 | 1 | 未创建 | 未创建 |
| 前两块完成，开始第三块 | 0 | 0 | 1 | 未创建 |
| 整段完成 | 0 | 0 | 0 | 0 |

表中的 0.5 只是教学用状态。真实模型的噪声日程可以不均匀，也不一定经过这个值。关键在于，向下推进视频时，已经生成的块保持固定，当前块在自己的去噪时间上继续更新。\(\tau\) 的变化描述 latent 如何去噪，与画面中人物走了几秒没有直接对应关系。

在模型支持相应条件接口时，新输入的控制信号可以影响尚未生成的块。已经播放的块无法因此改写。块越长，模型能同时协调的局部运动越多，用户通常也要等待更久才能收到第一块。

## 块内双向与块间因果怎样同时成立

因果注意力限制一个查询可以读取哪些键。对四个块，允许关系可以写成下面的矩阵。行是查询所在块，列是键所在块，1 代表允许读取。

```text
              key block
              1  2  3  4
query block 1 1  0  0  0
            2 1  1  0  0
            3 1  1  1  0
            4 1  1  1  1
```

对角线上的每个 1 可以代表一整个密集注意力子矩阵。于是第三块内部的空间位置和 latent 帧可以互相交换信息，第三块也能读取第一、第二块，但读不到第四块。若每块包含 \(b\) 个 token，token 从 0 开始编号，块因果掩码为

\[
M_{ij}=\begin{cases}
0,&\lfloor j/b\rfloor\leq\lfloor i/b\rfloor,\\
-\infty,&\text{其他情况},
\end{cases}
\]

并加入注意力分数

\[
A=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}+M\right).
\]

这里用 0 和负无穷表达加法掩码，与前面用 1 和 0 表达允许关系是同一规则。负无穷位置经过 softmax 后权重为零。掩码在所有需要因果约束的层生效，才能防止信息经另一条网络路径泄漏。

[CausVid](https://arxiv.org/html/2412.07772v2#S4.SS1) 使用块内双向、块间因果的设计。生成粒度是一个块，块内较早的帧仍然可能依赖同块较晚的 latent 帧。把这种结构称为块因果，比笼统地说“每帧都只能看过去”更准确。

视频系统里还存在几种不同的因果要求。[因果 VAE](video-vae-1029-1246.md)控制编码或解码如何利用时间邻域；块因果 DiT 控制生成主干如何读取视频上下文；动作条件世界模型还需要建立动作与未来变化的关系。它们需要各自的结构、数据和验证，不能由其中一个标签推导另外两个。尤其是只在 VAE 上使用因果卷积，并不会自动把双向 DiT 变成流式生成器。

## 为什么用真视频训练，连续生成时仍会越走越偏

训练一个预测下一块的模型，最直接的做法是给它真实前缀，让它还原当前带噪块。设真实前缀为 \(z^{(<k)}\)，当前块采用线性加噪

\[
z_\tau^{(k)}=(1-\tau)z^{(k)}+\tau\epsilon^{(k)},
\qquad u^{(k)}=\epsilon^{(k)}-z^{(k)}.
\]

一种对应的 Flow Matching 损失是

\[
\mathcal L_{\mathrm{TF}}
=\mathbb E\left[
\left\|
 v_\theta(z_\tau^{(k)},\tau,z^{(<k)},c)-u^{(k)}
\right\|^2
\right].
\]

这里的速度方向与本文“噪声端为 1”的约定一致，采样需要向较小的 \(\tau\) 积分。公式用来说明 teacher forcing 的条件来源，不声称所有论文都采用同一种参数化。其他噪声预测或干净样本预测目标也会遇到同样的上下文问题。

训练时，前缀来自真实视频；运行时，前缀是模型已经生成的 \(\hat z^{(<k)}\)。如果前一块把手的位置画偏了，模型下一块面对的就是一段偏移过的动作。它可能继续这个偏移，也可能突然把手拉回训练中常见的位置，形成跳变。这种差别通常称为 exposure bias，即训练时很少接触自己生成的上下文。

用一个明确的局部误差模型可以看出累积条件。假设相邻两块之间，误差近似满足

\[
e_{k+1}\approx a e_k+\delta_k.
\]

\(a\) 表示当前生成器对前缀扰动的敏感程度，\(\delta_k\) 是新引入的误差。取教学值 \(e_1=0.1\)、\(a=1.2\)、每步 \(\delta_k=0.05\)，后续误差依次为 0.17、0.254、0.3548。若 \(|a|<1\)，历史扰动会衰减，持续的新误差仍可能留下稳定偏差。真实视频误差是高维、非线性的，这组数只说明“每块误差小”不足以保证“长序列始终稳定”。

Teacher forcing 的单步去噪损失能够下降，同时长视频中的身份、位置或色调误差继续增长。这两种现象没有矛盾，因为它们使用的上下文分布不同。

可以把这个差异变成可检查的实验。固定后续块的条件和初始噪声，一组读取真实前缀，另一组读取学生自己生成的前缀，逐块比较身份、位置和动作。若第二组从某一块起明显退化，而第一组仍稳定，训练与部署的上下文差异获得了直接证据。还可只对真实前缀施加一个已知位置扰动，观察后续模型是平滑接住、纠正还是放大它。

这两个对照回答不同问题。真实与自生成前缀的差异包含许多复杂错误；单一扰动只能测局部敏感性，不能代表所有自生成失败。前面的 \(a\) 可以由小扰动近似估计，却不能把某次估计外推为无限长视频稳定性的证明。随后引入 forcing 的训练变化，正是要改变模型在这些前缀状态上获得的监督。

## Diffusion Forcing 改变了哪些训练输入

[Diffusion Forcing](https://arxiv.org/html/2407.01392v3) 让不同序列位置独立抽取噪声级别。对视频块，可以写成

\[
z_{\tau_k}^{(k)}=(1-\tau_k)z^{(k)}+\tau_k\epsilon^{(k)}.
\]

一段四块训练样本可能具有 \((\tau_1,\tau_2,\tau_3,\tau_4)=(0.1,0.7,0.3,0.9)\)。模型接收每块的噪声信息，按照因果依赖去噪。这样，训练会遇到不同确定程度的历史，生成时也可以安排不同位置采用不同去噪进度。若噪声采样方案包含干净端点，“干净历史加带噪当前块”就能直接出现在训练中；连续时间采样若不抽端点，则需要留意端点附近的覆盖和具体实现。

这比整段视频始终共用一个噪声量更灵活，也能训练模型利用不完全可靠的历史。不过，这些带噪历史通常仍由真实视频加高斯噪声构造。模型自己生成的错误可能是一只多出的手、消失的物体或错误的事件顺序，其分布与高斯扰动不同。因此，独立噪声级别扩展了训练状态的覆盖范围，仍需要检查真实滚动生成时的误差。

这里还有一个容易混淆的词。Diffusion Forcing 中的一个 token 可以对应一个高维连续观测，如一帧或一块 latent。它并不要求先把视频变成离散词表，再像文本一样逐个采样整数 token。读其实现时，要先确认序列位置和空间 token 分别在哪一层表示。

## CausVid 与 Self Forcing 分别补上哪一段

CausVid 关注如何把已有的双向、多步视频扩散模型转换为少步的块因果生成器。论文先用双向教师生成的 ODE 轨迹初始化学生，再使用分布匹配蒸馏训练因果学生。教师可以看完整视频，学生只能使用当前块和历史；两者的注意力依赖不同，因此论文称这一过程为非对称蒸馏。论文给出从 50 步教师到 4 步生成器的设置，这个数字描述其特定实验，不能直接代替其他模型的速度测量。

这些少步学生的采样接口还需要单独读取。CausVid Algorithm 2 和 Self Forcing 的相应流程先预测干净块，再按下一噪声级别重新加噪，可概括为 \(z_{\tau'}=\alpha_{\tau'}\hat z_0+\sigma_{\tau'}\epsilon'\)。系数由该学生训练时采用的路径定义，\(\epsilon'\) 是新采样的噪声，最终干净端不再加噪。这与直接把局部速度交给 Euler 积分的接口不同，不能把另一篇文章里的 solver 原样套到所有少步模型上。

这里的分布匹配蒸馏不要求学生逐帧复制某条固定教师视频。DMD 利用数据分布与生成分布的 score 估计，给生成器提供调整分布的梯度。具体梯度和辅助模型见[扩散蒸馏](distillation.md)。CausVid 的 Algorithm 1 从数据视频逐块构造不同噪声量的输入，让学生预测干净块，再拼成视频计算 DMD 监督。这个训练输出没有经历推理时完整的逐块生成过程。因此，虽然目标已经上升到视频分布，送入目标的样本分布与实际流式生成分布仍有差别。

[Self Forcing](https://arxiv.org/html/2506.08009v1) 把训练中的上下文来源向实际采样过程靠近。它在训练时也逐块生成，第二块读取模型自己生成的第一块，第三块读取自己生成的前两块。生成完整片段后，再用视频级分布匹配目标评价这段输出。论文研究了 DMD、SiD 和 GAN 等目标，机制上的共同点是把监督放在模型连续生成的视频分布上。

这样一来，模型训练时能遇到自己的上下文偏差。但把所有块、所有去噪步骤的计算图都保留到反向传播，会消耗大量显存。Self Forcing 使用少步模型，并随机选择去噪截断位置，只通过所选终止步骤反向传播，同时截断历史 KV cache 中的梯度。每轮随机选择位置，使不同去噪步骤有机会收到监督。它保留了自生成上下文的前向过程，并使用截断梯度控制训练成本；这不等同于对无限长 rollout 做完整反向传播。

这三个名字对应的改动可以放回同一条数据流。

| 方法 | 当前块训练时看到的历史 | 核心改动 |
| --- | --- | --- |
| Teacher forcing | 真实的干净前缀 | 直接学习给定真实历史的条件生成 |
| Diffusion Forcing | 真实序列在各位置独立加噪后的前缀 | 扩展噪声状态与采样日程的组合 |
| CausVid | 数据视频在各块独立加噪后的历史 | 用双向教师、初始化和分布匹配得到少步因果学生 |
| Self Forcing | 模型在训练中逐块生成的前缀 | 让视频级监督作用于自回归 rollout，配合梯度截断 |

这张表只比较上下文与训练方式。实际质量还依赖底层视频模型、数据、目标、块长和推理设置。训练中使用自己的输出能针对 exposure bias，并不能证明所有时长、场景和动作都不会退化。

## KV cache 为什么必须区分带噪状态与干净历史

一个 Transformer 层把输入隐状态 \(h\) 投影成 \(K=hW_K\)、\(V=hW_V\)。缓存可以节省计算的前提是，同一份历史在后续调用中本来就会产生相同的 K 和 V。

联合去噪中的视频 latent 会在每个 \(\tau\) 改变，噪声时间嵌入也会改变隐状态。下面用一个刻意简化的标量模型说明误用缓存的结果。取干净值 \(z_0=2\)、噪声 \(\epsilon=0\)，设 \(z_\tau=2(1-\tau)\)、\(h=z_\tau+\tau\)、\(K=2h\)、\(V=3h\)。

| 噪声时间 | 输入 \(z_\tau\) | 隐状态 \(h\) | K | V |
| --- | --- | --- | --- | --- |
| 0.75 | 0.5 | 1.25 | 2.5 | 3.75 |
| 0.25 | 1.5 | 1.75 | 3.5 | 5.25 |

如果一个查询只允许读取这一条键，softmax 权重恒为 1，它在第二次调用时应该读到 V=5.25。复用第一次的缓存只能得到 3.75，差异来自过期状态，无须复杂网络就能出现。真实 DiT 还有时间调制、归一化、位置编码和多层传播，不能默认旧噪声步骤的 K/V 仍然有效。

已经生成的干净历史具备不同条件。若历史块固定在干净时间，噪声时间嵌入固定，位置与外部条件保持一致，且所有相关计算都不会读取未来，那么新增块不会改变此前的历史表示。在这种设计下，可以把干净前缀的各层 K/V 保留下来，让当前带噪块反复查询。

[CausVid 的 Algorithm 2](https://arxiv.org/html/2412.07772v2#S4.SS4) 明确区分这两步。当前块先完成若干次去噪，再对最终干净块以时间 0 做一次前向，计算可追加到历史缓存的 K/V。最后一次带噪输入产生的中间缓存，不能无条件当作干净块缓存。

整段并行训练时，未来块已经在输入中，需要显式块因果掩码。逐块推理时，若提供的 key 只有干净历史和当前块，未来块根本不在可见集合里，就可以在这个集合上调用双向高效注意力 kernel。因果约束在此由输入范围和缓存组织保证，不能只凭 kernel 名称判断模型是否因果。

完整缓存键还隐含模型权重、层号、位置、注意力规则和条件。切换提示词、改变噪声调制方式或重新编号位置以后，是否还能复用历史，取决于模型的条件设计和实现约定。若历史计算本应受新条件影响，就需要重算或使用为提示切换专门训练的方案。跨去噪步的近似特征缓存则是另一类加速方法，必须另外测量它引入的误差。

## 四块视频怎样使用两块大小的滚动缓存

设每个视频块包含 3 个 latent 帧，缓存最多保留两个已完成块，当前正在去噪的块使用独立工作区。下面只规定块级依赖，不假设每块一定对应相同数量的 RGB 帧，实际映射仍由 VAE 的首帧和时间压缩规则决定。

| 正在生成 | 可查询的干净历史 | 完成后保留的历史 | 此时发生的动作 |
| --- | --- | --- | --- |
| 第一块 | 空 | 第一块 | 去噪，计算干净 K/V，开始解码 |
| 第二块 | 第一块 | 第一、第二块 | 当前块多次读取同一份历史 |
| 第三块 | 第一、第二块 | 第二、第三块 | 第三块完成后移除第一块的缓存 |
| 第四块 | 第二、第三块 | 第三、第四块 | 第四块无法直接查询第一块 |

第一块缓存被移除后，第二、第三块的表示里仍可能包含传播过来的信息，但它们不能保证完整保存第一块的一切细节。物体离开视野很久以后再次出现，模型可能已经失去准确恢复其身份所需的可访问信息。固定大小的缓存允许生成长度继续增加，可直接读取的上下文仍然有限。

滚动时还要保持位置编码语义。如果保留的 K 使用了原始位置编码，随意把它们的索引从 `[3,4]` 改成 `[0,1]`，再让新 Q 使用另一套编号，原有相对关系就可能改变。实现需要一致地处理缓存位置和新查询位置。删除旧 K/V 后继续使用保留项，也一般不等于“把最近两个原始块从头重新编码”。保留项是在更早的上下文下算出的，可能间接含有已经移除的信息。滚动缓存定义了一种持续更新的模型状态，训练和评测都应覆盖这种状态。

Self Forcing 在论文中报告，直接滚动缓存会遇到训练与推理不一致的问题。其基座 VAE 的首个 latent 帧只编码首张图像，后续 latent 还进行了时间压缩；滚动到看不到首个 latent 时，模型面对的前缀分布发生变化。作者通过训练时限制局部注意力，让最后一块也经历看不到第一块的情形。这一具体观察解释了为什么“把最老的缓存删掉”还不足以完成长视频适配，也不能推广成所有 VAE 都会有相同的首帧质量差异。

缓存有实际显存成本。设 batch 为 \(B\)，层数 \(L\)，KV 头数 \(H_{kv}\)，每头维度 \(d\)，缓存 token 数 \(N_c\)，每个元素 \(s\) 字节，忽略分配器和额外元数据时

\[
\text{KV bytes}=2BLH_{kv}dN_cs.
\]

前面的 2 对应 K 和 V。以一个纯教学配置计算，\(B=1\)、\(L=24\)、\(H_{kv}=32\)、\(d=128\)、\(N_c=4096\)、\(s=2\)，缓存占 1,610,612,736 字节，即 1.5 GiB。模型权重、当前块激活和解码器还需要额外显存。这组数字不代表某个现成视频模型的配置。

VAE 的 chunk cache 又保存另一种状态，通常用于延续时间卷积或相应模块的历史特征。DiT 的 KV cache 保存注意力历史。两个缓存属于不同计算阶段，清空其中一个可能造成不同类型的边界跳变。它们都需要随着一次视频生成正确初始化、更新和释放。

## 少步、低延迟与高吞吐怎样分别测量

把每块去噪调用从 50 次减到 4 次，减少的是噪声时间方向上的计算次数。视频仍可包含相同的帧数和播放时长。反过来，把一段视频切成更多小块，改变的是视频时间方向上的生成粒度；如果每块仍需要很多次去噪，首块等待时间依然可能很长。

一个粗略的首块延迟分解为

\[
T_{\mathrm{first}}
\approx T_{\mathrm{condition}}
+S\,T_{\mathrm{denoise}}(b,N_c)
+T_{\mathrm{cache}}
+T_{\mathrm{decode}}
+T_{\mathrm{transfer}}.
\]

这里 \(S\) 是当前块的去噪调用数，\(b\) 是当前块 token 数，\(N_c\) 是历史缓存 token 数。真实系统的调用成本会随历史长度、CFG 计算、kernel、并行和编译状态改变。这条式子用于定位成本，不是精确性能预测。

NFE 表示网络函数评估次数，报告时必须说明计数口径。四个采样时间步不一定只做四次网络计算。例如 CFG 可以分别评估有条件与无条件分支，也可以把两者合并在一个 batch 中执行；合并调用并没有取消两份样本的工作量。干净块的缓存写入可能再需要一次前向。只报告采样步数会漏掉这些成本。

首块低延迟决定用户多久能看到画面，持续生成吞吐决定播放会不会随后卡住。若目标播放速度为 24 FPS，每次交付 12 帧，对应约 0.5 秒播放时间。生成和交付下一块平均需要 0.4 秒，有机会持续播放；平均需要 0.7 秒，已有缓冲迟早被耗尽。即使平均为 0.4 秒，偶发长延迟也可能产生停顿，因此还要观察延迟分位数和缓冲需求。

比较两个系统时，应固定分辨率、帧数、播放帧率、硬件、精度、batch、CFG、预热状态，并说明是否包含 VAE 解码和数据传输。离线大批量吞吐和单请求交互延迟可以相差很大，不能用其中一个替另一个作结论。

## 长视频质量需要沿时间检查

一个完全静止的视频容易保持背景稳定，也容易得到低闪烁。它仍可能没有完成提示中的跑动、转身或镜头移动。[VBench](https://arxiv.org/html/2311.17982v1) 因此分别评估主体一致性、背景一致性、闪烁、运动平滑度与动态程度等维度。原始 VBench 使用 DINO 特征评估主体一致性、CLIP 特征评估背景一致性，并用 RAFT 估计动态程度。每个指标观察的是某种信号，特征相似或运动平滑不能证明物理过程正确。

对长视频，整段平均分还可能掩盖后半段退化。可以把同一批生成结果按开始、中段、末段分组，分别观察主体身份、物体数量、运动幅度、文本遵循和接缝处的亮度变化。再把首块、缓存开始淘汰的位置、VAE 分块边界单独取出检查，才容易分清问题来自哪段机制。

例如，一个人物进入遮挡区再出现的测试，同时检查长期身份与可见性变化。仅比较相邻帧特征，可能漏掉遮挡前后身份已经改变的情况。一个物体被拿起后放下的测试，可以检查手物接触、位置连续和事件顺序。测试提示与随机种子应预先固定并保留失败样本，不能只展示挑出的成功片段。

如果目标进一步变成动作条件世界模型，还要改变验证方式。同一个初始状态施加不同动作，预测应出现相应变化；预测出的轨迹需要与实际环境转移对照；模型用于规划时，还要测试执行后重新观察、再作决策的结果。开放生成的视频自然度无法直接回答这些问题，相关机制见[生成式模拟与视频世界模型](../world-models/generative-simulation-and-video.md)。
