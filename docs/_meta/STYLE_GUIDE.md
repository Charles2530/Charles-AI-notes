# 写作规范：消除套话与冗余导航

适用范围：`前置数学知识` 及后续所有知识专题下的正文页面（不含索引页，索引页另有独立规范）。

## 背景

侧边栏（见站点左侧目录）已经承担了"同专题内有哪些页面"这一导航职责。正文的
唯一任务是把一个数学/工程概念讲清楚：直觉是什么、公式在说什么、在下游 AI
文章里叫什么名字、边界在哪、能解释什么现象。凡是不服务于这五件事的内容，
一律视为可删的套话。

## 禁止模式（正文中出现以下写法一律改写或删除）

### 1. "不是……而是……"开场公式
错误示例：
> "线性代数不是只为了算矩阵乘法。它给模型提供了一种表示世界的方式……"

改为直接陈述，不立稻草人：
> "线性代数给模型提供了一种表示世界的方式：把 token、图像 patch……"

判断标准：如果删掉"不是 X"这半句，句子依然完整且信息不变，就删。

### 2. 与侧边栏重复的导航板块
以下标题下的内容，只要链接的页面已经在侧边栏同级/同组出现，整段删除：
- "本专题相关"
- "站内下一步"（如果指向的是同组内的兄弟页面）
- 任何形式的"读到这里……可以横向补读"类引导句

只保留：MkDocs 自带的上一页/下一页（已由框架提供，不需要正文重复）；
真正的站外资料链接（不同专题的深度延伸，或外部资料）可以保留，
但不需要单独的过渡句包装，直接列出即可。

### 3. 低密度过渡句 / 连接词
如"更细一点看："、"换句话说"、"这里再补充一点"——如果去掉这句话，
后面的列表或段落依然能独立成立，就删，让内容直接衔接。

### 4. 开头/结尾重复总结
一篇文章的"这篇要解决什么问题"只在开头说一次，"读完能解释什么"只在
结尾说一次。检查开头引言和结尾收尾是否在用不同措辞重复同一件事，
如果是，合并或删掉一处。

### 5. 元话语（关于"这个专题/这篇文章是怎么组织的"的自我说明）
不属于概念本身、只是在描述写作方式或站点结构的句子，一律删除或移至
非正文的内部文档（如写作模板）。判断标准：这句话说的是"我们是怎么
写/组织这些内容的"，还是"这个概念是什么"——前者删，后者留。

## 必须保留的结构（这是本站价值所在，不要精简）

1. **概念对照表**（如"常见名词可以这样读"、"符号在说什么"）——具体、
   可查、把数学符号和代码/工程概念一一对应，这是读者真正需要的内容。
2. **公式 + 拆解**——公式本身加上"这里 X 是……，Y 是……"的逐项说明。
3. **常见误读表**——"误读 / 更稳的理解"对照，直接对应"近似在什么条件
   下成立，最容易被误读"。
4. **收尾锚点**——"看到 X 时先问三件事……"这类可执行的判断清单，
   帮读者把数学符号翻译回机制。保留且只出现一次。

## 一句话判断标准

改写或删除任何一段前，问：**这段话是在讲这个数学概念本身，还是在讲
"我们打算怎么讲这个概念"？** 前者留，后者删。
