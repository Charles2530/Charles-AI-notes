# 本地 AI 阅读助手设计

## 状态

- 日期：2026-08-25
- 状态：已确认，等待实施计划
- 适用范围：仅本地 `make serve` 阅读场景
- UI 方向：桌面端右下角抽屉，移动端底部抽屉

## 背景

Charles AI notes 是一个 MkDocs Material 静态知识库。用户希望在阅读博客时选中文字，向 AI 询问相关问题，并在当前文章内继续追问。功能仅供本地使用，不要求部署公网服务。

仓库虽然包含 GitHub Pages 工作流，但当前仓库及 Pages 地址均未提供匿名公网访问。本设计不新增公网部署能力。

## 已验证的模型能力

2026-08-25 已用最小请求验证以下配置：

- Provider：iLab OpenAI-compatible gateway
- Base URL：`https://47.95.249.76`
- Responses 路径：`/responses`
- 模型：`gpt-5.6-sol`
- 推理强度：`high`
- 响应存储：`store: false`

普通响应与流式 SSE 响应均返回 HTTP 200。流式响应包含 `response.output_text.delta` 和 `response.completed` 等事件，测试输出与预期一致。

API Key 不写入本文档、前端资源、测试或 Git 历史。Codex 配置中的 `sandbox_mode`、`approval_policy`、`forced_login_method`、`fast_mode` 等客户端选项不属于博客 API 请求参数。本功能不发送未经验证的 `service_tier` 参数。

## 目标

1. 执行 `make serve` 后，博客与本地 AI 服务同时可用。
2. 用户选中正文后可一键引用，并向 AI 提问。
3. AI 获得选中文字、所在段落、文章标题和当前页面内的对话历史。
4. 同一文章内支持多轮追问，切换文章后自动清空。
5. 回答以流式文本展示，并安全呈现段落、列表、行内代码和代码块。
6. AI 不可用时不影响博客启动或阅读。
7. API Key 仅存在于本机服务端环境中。

## 非目标

- 不提供公网 AI 接口或公网部署。
- 不实现用户账号、跨设备同步或长期对话存储。
- 不实现永久划线、高亮笔记或知识库检索。
- 不把完整文章自动发送给模型。
- 不允许模型返回的 HTML 在页面中直接执行。

## 方案选择

### 采用：独立本地 AI 代理

`make serve` 作为统一入口，同时运行 MkDocs 和仅绑定回环地址的 AI 代理。前端只访问本地代理，由代理读取 Key 并调用 iLab。

选择原因：

- 不把 Key 暴露给浏览器。
- 不依赖 MkDocs 或 livereload 的内部路由实现。
- 可以独立测试配置、请求校验、上游调用、流式转换和日志。
- AI 故障不会阻断静态博客。

### 未采用：MkDocs 内部插件路由

优点是启动入口统一，但需要依赖开发服务器内部实现，升级风险较高。

### 拒绝：浏览器直连 iLab

该方案会把 Key 暴露在前端代码、浏览器存储或网络调试信息中，不满足安全要求。

## 架构

本地服务由以下单元组成：

1. **启动协调器**
   - 由 `make serve` 调用。
   - 启动本地 AI 代理和 MkDocs。
   - 将代理的详细诊断写到当前终端。
   - MkDocs 退出时关闭代理；收到中断信号时清理子进程。

2. **AI 代理**
   - 默认绑定 `127.0.0.1:8765`。
   - 提供健康检查和聊天流式接口。
   - 从系统环境或被 Git 忽略的 `.env.local` 读取 Key。
   - 即使 Key 缺失或上游不可用，代理仍可启动并返回未就绪状态。

3. **阅读助手前端**
   - 作为 MkDocs 全局本地 JavaScript 加载。
   - 负责选区检测、上下文提取、抽屉状态、页面内对话和流式渲染。
   - 通过 `window.document$` 兼容 MkDocs instant navigation 的重新挂载行为。

4. **样式层**
   - 沿用现有青绿、暖橙、纸张白的 Atlas 视觉变量。
   - 桌面端使用右下角抽屉；窄屏使用底部抽屉。

## 本地配置

本地配置支持以下环境变量：

- `OPENAI_API_KEY`：必需，除非写入 `.env.local`。
- `ATLAS_AI_BASE_URL`：默认 `https://47.95.249.76`。
- `ATLAS_AI_MODEL`：默认 `gpt-5.6-sol`。
- `ATLAS_AI_REASONING_EFFORT`：默认 `high`。
- `ATLAS_AI_ADDR`：默认 `127.0.0.1:8765`。

`.env.local` 必须加入 `.gitignore`。示例文件只提供变量名和安全默认值，不包含真实 Key。
同名系统环境变量优先于 `.env.local`，便于临时覆盖而不修改文件。

## UI 与交互

### 桌面端

- 默认显示右下角圆形 AI 入口。
- 在正文选中文字后，选区附近显示“问 AI”浮动按钮。
- 点击按钮打开约 20–24rem 宽的抽屉，并展示当前引用卡片。
- 抽屉包含标题、服务状态、清空、关闭、对话区和输入区。
- 回答支持复制；停止生成时保留已收到的文本。

### 移动端

- 使用底部抽屉，保留少量正文可见区域。
- 输入区固定在抽屉底部。
- 选区浮动按钮不能遮挡系统文本选择手柄。

### 键盘与无障碍

- `Enter` 发送，`Shift + Enter` 换行。
- `Escape` 关闭浮动按钮或抽屉。
- 抽屉、状态提示和流式回答提供适当的 ARIA 属性。
- 所有按钮均有文本标签或 `aria-label`，并具备可见焦点状态。
- 尊重 `prefers-reduced-motion`。

## 上下文提取

只有 `.md-content__inner` 正文中的非空选区可以触发功能。前端提取：

1. 选中文字。
2. 最近的完整段落、列表项、表格单元格或代码块。
3. 当前文章的一级标题。
4. 当前页面路径。

选区跨越多个块时，使用共同正文容器内涵盖选区的最小连续文本，并执行长度限制。导航、目录、页脚、聊天框和其他控件中的选区不会触发“问 AI”。

## 对话状态

- 每个页面拥有独立的内存态会话。
- 切换页面后清空消息和当前引用。
- 刷新页面后清空会话。
- 初次问题携带当前引用和段落。
- 未重新选择时，追问沿用当前引用。
- 重新选择后，新引用只用于下一条用户消息；已有对话继续保留。
- 每次请求最多携带最近 12 条消息，并限制引用、段落、问题和总请求长度。
- 不依赖 `previous_response_id`，而是显式发送有限历史，以保持 `store: false`。

## 请求与流式数据流

1. 前端向本地代理发送文章上下文、当前问题和有限对话历史。
2. 代理验证来源、Content-Type、请求体大小、字段类型和长度。
3. 代理构造中文阅读助手指令，要求区分文章上下文与模型通用知识，避免伪造原文结论。
4. 代理向 `https://47.95.249.76/responses` 发送：
   - `model: "gpt-5.6-sol"`
   - `reasoning: {"effort": "high"}`
   - `store: false`
   - `stream: true`
5. 代理只向浏览器转发必要的文本增量、完成和安全错误事件。
6. 前端通过 DOM 节点和 `textContent` 安全构造回答，不执行模型 HTML。

## 错误与日志

### 页面行为

无论是缺少 Key、鉴权失败、限流、超时、TLS、网络还是上游服务错误，页面统一显示：

> AI 服务暂时不可用，请稍后重试。

博客始终正常启动并可阅读。问题输入和已收到的回答保持可见，方便稍后重试。

### 终端日志

`make serve` 的终端输出记录：

- 时间
- 请求或启动阶段
- HTTP 状态码
- 延迟
- 安全的错误类别
- 必要的本地排查建议

日志不得记录：

- API Key 或 Authorization 头
- 文章原文与引用
- 用户问题
- 模型回答
- 上游可能包含凭证片段的原始错误正文

## 安全边界

- AI 代理只绑定 `127.0.0.1`。
- 只接受来自 `localhost` 或 `127.0.0.1` 博客页面的 JSON 请求。
- 对预检、来源、方法、Content-Type 和请求体大小进行限制。
- 不使用 `-k` 或其他方式绕过 TLS 证书验证。
- 不自动重发补全请求，避免重复调用和计费。
- 同一抽屉只允许一个活动生成请求。
- 用户可停止当前请求；代理应尽快关闭上游连接。
- 健康接口不返回 Key、完整配置或上游原始错误。

## 测试策略

遵循测试先行：先写失败测试并验证失败原因，再实现最小代码使其通过。

### 后端单元测试

- 环境变量与 `.env.local` 的读取优先级。
- Key 缺失时代理仍启动且健康状态为未就绪。
- 请求字段、长度、来源和请求体限制。
- iLab URL 拼接与 `/responses` 路径。
- 请求载荷包含正确模型、`reasoning=high`、`store=false` 和 `stream=true`。
- 安全错误分类与日志脱敏。

### 模拟网关集成测试

- 使用本地假网关返回 Responses SSE 事件。
- 验证文本增量、完成、中断、超时和上游错误。
- 验证停止生成会关闭客户端流并尝试关闭上游连接。
- 自动化测试不调用真实 iLab，不消耗 API。

### 前端契约测试

- 只有正文选区触发浮动按钮。
- 正确提取选中文字、所在块和标题。
- 新选区替换下一条消息的引用。
- 同页保留多轮、切页清空。
- UI 只显示统一错误文案。
- 模型输出不通过不受信任的 `innerHTML` 注入。
- 桌面和移动端样式、打印隐藏和 reduced motion 规则存在。

### 构建与人工验收

- 运行相关测试和完整测试集。
- 运行 `mkdocs build --strict`。
- 检查构建产物不包含 API Key。
- 最后用真实 iLab 执行一次本地端到端测试：划线、首次提问、连续追问、停止生成和离线降级。

## 验收标准

1. 有效 Key 与网络条件下，`make serve` 启动后可以完成真实流式问答。
2. Key 缺失或 iLab 不可用时，博客仍正常启动，页面只显示统一错误文案，终端显示可排查原因。
3. Key 不出现在 Git diff、静态构建产物、浏览器网络请求、页面源码或日志中。
4. 选区上下文包含选中文字、所在块和标题，不包含整篇文章。
5. 同页支持多轮，切页或刷新清空。
6. 桌面与移动端 UI 符合已确认的视觉稿。
7. 自动化测试与 `mkdocs build --strict` 通过。
