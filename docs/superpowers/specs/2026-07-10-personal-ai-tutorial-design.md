# Charles AI notes：分层教程与独立文章双层体系设计

## 文档状态

- 设计日期：2026-07-10
- 状态：用户已确认
- 目标读者：站点作者本人，一名深度学习研究者
- 核心定位：一套全面、清晰、可循序学习的个人 AI 教程，同时保留独立技术文章按问题查阅的能力

## 背景与问题

当前仓库已经拥有较强的内容基础：`files/` 下共有 348 个 Markdown 页面，其中 344 个参与发布，论文精读有 76 篇。主要问题不是内容数量不足，而是知识依赖、学习节奏和覆盖状态没有被清楚表达。

现状中的关键问题包括：

1. 首页把站点描述为独立博客集合，并建议首次访问者跳过总览，这与“个人系统教程”的真实定位冲突。
2. 344 个发布页面中只有 248 个进入导航；18 个已发布专题索引中有 13 个未进入导航。
3. 数学基础覆盖面较广，但多篇文章直接进入公式或应用，缺少足够的零基础直觉、符号解释、逐步推导和数值例子。
4. 基础知识、专题教程和论文精读之间缺少明确的知识依赖，读者难以判断应该先补什么。
5. 世界模型与具身智能内容丰富，但部分路线图、矩阵和趋势页职责重叠；强化学习、VLM 精细应用和 Agent 系统内容相对薄弱。
6. 论文精读已有良好的证据边界意识，但“研究背景 -> Challenge -> Finding -> 方法 -> 实验结论”的故事链尚未成为统一硬标准。
7. 导航、索引和自动检查存在漂移：主页论文数量过期、新增 DM0.5 漏论文索引、VLA 自动术语链接指向 VLM、测试和部分质量审计当前不通过。

## 目标

### 内容目标

1. 数学基础可以从零阅读，负责建立直觉、符号和推导能力。
2. 深度学习基础默认读者已经掌握站内数学基础，并建立后续专题共享的概念底座。
3. 训练、推理、量化、算子、扩散、VLM、强化学习、世界模型、VLA 和具身智能等专题默认读者已经掌握深度学习基础。
4. 每篇文章仍然可以独立阅读和搜索进入，不要求读者严格线性通读整站。
5. 论文精读可以独立阅读，但必须补齐理解论文所需的最小背景，并突出论文的 finding、方法因果链、实验价值和证据边界。

### 结构目标

1. 首页同时提供“按学习路径”和“按具体问题查阅”两个入口。
2. 每个专题索引同时提供推荐顺序和完整文章目录。
3. 全站拥有可维护的覆盖矩阵，明确已覆盖、需要补强、缺失待写和参考案例。
4. 所有发布页面必须满足以下条件之一：进入导航、进入对应专题完整目录，或被列入明确的内部页面白名单。

### 质量目标

1. 构建、测试、内容审计和结构审计形成统一门禁。
2. 不再依赖硬编码文章数量维护首页。
3. 新页面不能静默成为孤儿页面。
4. 不以批量套模板代替人工重写；模板约束逻辑功能，不强制所有页面使用完全相同的标题。

## 非目标

1. 本轮不一次性重写全部 348 个 Markdown 页面。
2. 本轮不批量删除图片、来源台账、`.tmp` 证据文件或 Git 历史。
3. 本轮不把站点改成只能从第一页顺序阅读的线性教材。
4. 本轮不为了导航整齐而大规模移动现有文章路径。
5. 本轮不机械地给 76 篇论文页添加相同段落；论文页按价值和问题逐步复查。

## 设计原则

### 双层阅读模型

同一批内容同时服务两种阅读方式：

- 教程层：通过首页、学习路径、专题索引、前置知识和覆盖矩阵形成循序渐进的课程。
- 文章层：每篇文章独立回答一个具体问题，可以从搜索、外链或完整目录直接进入。

独立文章不是教程体系的替代品，教程体系也不要求把独立文章合并成长章节。教程层只负责编排知识依赖和学习顺序，文章层负责完成具体解释。

### 渐进式知识依赖

全站采用四级知识依赖：

```text
数学基础（零基础）
  -> 深度学习基础（假设掌握数学基础）
    -> 专题教程（假设掌握深度学习基础）
      -> 论文精读与研究观察（独立进入，但补最小背景）
```

依赖表示默认起点，不表示硬性阅读门槛。文章遇到关键前置概念时，仍需在当前页给出一段足够理解本文的最小解释，再链接到完整基础页。

2. 如果从头学习，第一步去哪里。
3. 如果正在解决具体问题，如何进入完整目录或搜索。

首页主体包含：

- 从头学习：数学基础 -> 深度学习基础 -> 三条专题主线。
- 按目标学习：训练与系统、生成与多模态、决策与物理智能。
- 按问题查阅：完整文章目录、知识 QA、论文精读、搜索。
- 当前补全重点：只列少量高优先级缺口，不展示会快速过期的硬编码文章数量。

### 学习路径

新增 `files/learning-paths/index.md` 作为公开学习路径入口，并用 `files/learning-paths/coverage.md` 维护全站覆盖矩阵。学习路径承载三条主线：

1. 训练与系统：数学基础 -> 张量与计算图 -> Transformer 与训练 -> 分布式训练 -> 量化 -> 推理 -> 算子。

3. 决策与物理智能：概率与随机过程 -> 强化学习 -> 世界模型 -> VLA -> 具身智能与闭环评测。

当前 `roadmap/**` 继续作为待整理材料区。公开学习路径使用新的独立目录，避免把读者路线与维护规范混在同一页面。

### 专题索引

每个专题 `index.md` 统一承担以下职责：

1. 专题解决什么问题，以及与相邻专题的边界。
2. 前置知识。
3. 学习目标。
4. 推荐阅读顺序。
5. 完整文章目录。
6. 覆盖矩阵。
7. 学完后的检查问题。

推荐顺序是精选路径，完整目录必须覆盖该专题所有公开正文。导航可以保持精简，但专题索引不能遗漏公开文章。

## 单篇文章写作契约

### 所有文章的共同要求

每篇文章开头应让读者快速知道：

- 本文回答什么问题。
- 需要哪些前置知识。
- 读完以后能做出什么判断或完成什么任务。

每篇文章结尾至少包含：

- 核心结论。
- 常见误解或适用边界。
- 1 至 3 个自测问题或判断题。
- 真正有价值的下一步阅读。

文章不应通过自链接、写作规范链接或泛化的“继续探索”假装完成站内互链。

### 数学基础页

数学基础面向零基础读者，推荐逻辑顺序为：

```text
为什么需要这个概念
-> 具体直觉或图景
-> 所需符号
-> 定义与逐步推导
-> 最小数值例子
-> 在深度学习中的用途
-> 常见误解
-> 自测与下一步
```

约束：

1. 先使用具体对象，再抽象成符号。
2. 每个公式说明它在解决什么问题，并在出现处解释符号。
3. 推导不能省略会改变读者理解的中间步骤。
4. 至少包含一个可以手算、画图或用短代码验证的例子。
5. 明确指出该数学概念会在哪些基础页或专题页再次出现。

### 深度学习基础页

深度学习基础默认读者已经掌握对应数学页，推荐逻辑顺序为：

```text
核心困惑
-> 最小例子
-> 张量、Shape 或数据流
-> 核心机制
-> 必要公式
-> 最小代码或计算示例
-> 失败模式
-> 小结与自测
```

基础页必须建立可复用概念，避免过早引入某篇前沿论文的局部术语作为主叙事。

### 专题教程页

专题页默认读者已理解深度学习基础，推荐逻辑顺序为：

```text
研究或工程问题
-> 已有方法为什么不够
-> 设计空间
-> 核心机制
-> 实现或系统链路
-> 成本与取舍
-> 评测、故障与验收
```

专题页只补当前问题需要的最小基础回顾，不重复整套基础教程。

## 论文精读标准

论文精读继续保持独立文章形式，并采用因果连贯的故事结构。这里的“故事”不是华丽语言，而是说明一个研究问题如何因为新的 finding 变得可解。

### 必须覆盖的逻辑功能

1. 研究背景：相关领域和已有工作在做什么。
2. Challenge：论文解决什么问题、问题的含义、困难来源、研究价值。
3. Finding：作者改变问题看法的关键洞见。
4. 方法：finding 如何导出模型、数据、目标函数、训练框架和推理路径。
5. 实验与结论：每个主要实验验证什么、设置是什么、结果是什么、作者得到什么结论。
6. 关键术语：使用 `English Name（中文翻译）：解释`。
7. 阅读结论：论文价值、可复用机制、局限、不能外推项和下一步证据。

### Finding 与技术贡献的边界

Finding 不是模型模块、loss 名称或训练技巧的列表。合格的 finding 需要回答：

- 过去为什么认为问题难解。
- 作者换了什么观察角度。
- 新角度如何把原问题转化为可处理的问题。
- 技术贡献为何自然地从这个洞见产生。

如果论文没有清楚提出单一 finding，精读应保守说明最接近 finding 的设计判断，而不能凭空创造作者观点。

### 方法解释要求

方法部分按论文实际披露情况拆分：

- 模型架构：各模块输入、输出和信息流。
- 数据：来源、混合、过滤、标注或合成过程。
- 表征与 tokenizer：输入如何变成模型可处理的状态。
- 目标函数：每个优化对象和条件变量。
- 训练阶段：预训练、微调、SFT、RL、蒸馏、冻结与解冻顺序。
- 优化和系统：精度、并行、硬件、上下文和调度。
- 推理与部署：训练后实际执行的路径和成本。

论文未披露的细节必须明确写“论文未说明”，不能补写推测参数。

### 实验解释要求

每个主要实验至少回答：

1. 实验要验证哪条 claim。
2. 数据、任务、指标、baseline 和关键设置是什么。
3. 结果中最重要的数字或趋势是什么。
4. 这项结果能支持什么。
5. 这项结果不能证明什么。

需要区分 Paper Result、Ablation、System Throughput、Closed-loop、Official Demo、Author Code、Independent Reproduced 和 Site Inference。

## 覆盖矩阵

覆盖状态统一为：

- 核心已覆盖：主干概念和必要解释已经存在。
- 需要补强：已有页面，但节奏、例子、推导或边界不足。
- 缺失待写：知识链中缺少独立页面或关键中间层。
- 参考案例：论文精读、趋势观察或专项案例，不承担基础教程职责。

当前全站初始判断如下：

| 板块 | 初始状态 | 主要动作 |
| --- | --- | --- |
| 数学基础 | 覆盖较广、深度不均 | 优先重写直觉、符号、推导和例子 |
| 深度学习基础 | 覆盖较强、依赖不清 | 建立顺序，补代码、失败模式和自测 |
| 训练与系统 | 内容丰富、入口不足 | 补全索引和导航，减少隐藏页面 |
| 扩散模型 | 主干较完整 | 优化顺序和公式解释 |
| 强化学习 | 中间层缺失 | 补 Q-learning、offline RL、reward/verifier、credit assignment |
| VLM | 架构和评测已有 | 补 OCR、文档/图表、grounding、GUI/屏幕 Agent |
| Agent / RAG | 内容分散 | 补 Agent runtime、工具状态、安全和评测 |
| 世界模型 / VLA / 具身 | 内容丰富但重叠 | 收敛路线图和矩阵职责 |
| 论文精读 | 数量多、方向不平衡 | 强化故事线并补少量经典锚点论文 |

论文锚点优先补强 VLM、RL/后训练、量化和算子方向；在核心教程缺口补齐前，不继续大量增加世界模型与具身论文数量。


## 自动检查与验收

### 结构检查

新增结构审计需要验证：

1. `mkdocs.yml` 中的目标文件存在且不重复。
2. 每个公开正文进入导航或对应专题完整目录。
3. 内部页面只通过显式白名单豁免。
4. 专题索引中的本地链接有效。
5. 论文精读索引覆盖所有论文正文。
6. 不存在未登记的无导航、无入链页面。

### 内容检查

1. 数学核心页具有直觉、公式解释、例子、AI 应用和自测。
2. 基础核心页具有前置知识、数据流或 Shape 解释、机制、失败模式和自测。
3. 论文新页具有背景、Challenge、Finding、方法、实验、术语、局限和阅读结论。
4. 下一步阅读不得以自链接或面向作者的写作规范代替。

### 最低验证命令

实施完成后至少运行：

```bash
pytest -q
python scripts/content_quality_report.py --include-hints
python scripts/paper_deep_dive_audit.py --include-hints
python scripts/math_rendering_report.py --fail-on-issues
python scripts/repro_status_audit.py

```

新增的结构审计进入 `make quality` 或统一的 `make check`，并在 CI 的 pull request 和 main push 上运行。

图片审计需要先修正 SVG 和微小尺寸放大的误报，再将真实高风险项纳入硬门禁。历史大文件和未引用图片只生成治理报告，不在内容重构中自动删除。

## 兼容与风险控制

1. 第一阶段保持现有文章路径，避免破坏旧链接。
2. 导航标签保持短小，正文 H1 不再自动覆盖全站导航标签；论文导航排序逻辑仅作用于论文分组。
3. 实施开始前重新记录完整工作区状态；所有届时存在的已修改、已删除和未跟踪文件均视为用户并行改动。仅在任务确实需要时逐文件阅读和合并，不得按设计阶段的旧清单覆盖。
4. 世界模型重复页面先定义职责和差异，再决定合并或归档。
5. 来源台账先判断是读者证据页还是内部维护元数据，再决定导航位置。
6. 设计文档位于 `docs/superpowers/specs/`；实施时需要同步修正 README 中把 `./docs` 作为 Conda 环境前缀的约定，避免文档与本地环境目录冲突。

## 验收标准

设计完成后的站点应满足：

1. 新读者从首页可以明确选择从数学开始或按问题查阅。
2. 每个专题都能看到前置知识、学习目标、推荐顺序和完整目录。
3. 任意公开文章都能从导航、专题索引或全文搜索中被发现。
4. 数学核心页可以被没有相关数学背景的读者独立理解。
5. 深度学习基础页明确依赖哪些数学知识，并能支撑后续专题。
6. 专题页不重复基础教程，而是说明机制、取舍和验收方法。
7. 新增论文精读能清楚区分 finding 与技术贡献，并逐项解释实验价值和证据边界。
8. 构建、测试、结构审计和内容审计全部通过，且最终差异核对证明没有覆盖任何实施前或实施期间出现的用户并行改动。
