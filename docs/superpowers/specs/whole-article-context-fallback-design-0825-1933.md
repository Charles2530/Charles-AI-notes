# AI 阅读助手全文上下文回退设计

## 目标

AI 阅读助手应当随时可以直接提问，不再强制用户先在正文中划线。划线仍然是更精确的上下文选择方式：有有效选区时使用选区和相关段落；没有选区时使用当前文章全文。

## 交互行为

- 用户直接打开聊天框时，可以立即输入和发送问题。
- 没有划线时，输入框提示为“询问整篇文章…”，不显示“当前引用”卡片。
- 有划线时，继续显示当前引用，并优先发送选中文字及其所在正文块。
- 用户移除当前引用后，聊天框回退到整篇文章模式，而不是禁止发送。
- Material 即时导航切换页面后，全文上下文必须从新页面重新读取；旧页面的选区和对话继续按现有逻辑清理。

## 上下文解析

提交问题时调用统一的上下文解析函数：

1. 如果 `state.reference` 存在，返回现有选区引用。
2. 否则读取当前 `.md-content__inner`，从 `h1` 或页面标题取得标题，从正文 `innerText` / `textContent` 取得规范化纯文本，并记录当前路径。
3. 正文不存在或清理后为空时，不向上游发送空上下文；界面沿用“AI 服务暂时不可用，请稍后重试。”的温和失败方式，并在本地控制台记录安全错误类别。

全文只读取文章容器，不包含导航、搜索框、AI 抽屉或阅读工具。空白会被规范化，同时保留段落换行，便于模型理解结构。

## 请求大小平衡

保留现有 128 KiB 请求上限。构造请求后按以下顺序缩减：

1. 从最旧的历史消息开始移除。
2. 如果仍超限，则按 UTF-8 字节预算缩短全文 `context`。
3. 不截断当前问题；选区模式继续使用现有较小的引用范围。

因此常规文章会完整发送，超长文章会在不破坏请求协议的前提下安全截断，不会因全文模式导致 413 或本地代理拒绝。

## 实现边界

- 仅修改前端上下文选择和提示文案，不修改 API Key、模型、代理端口或公网访问策略。
- 不增加新的依赖，不在页面加载时预先复制全文。
- 全文在每次提交时读取，以适配即时导航和页面内容更新。

## 测试与验收

- 无选区时可以构造包含文章标题、路径和正文的请求。
- 有选区时继续优先使用选区引用。
- 移除引用后自动使用全文。
- 超长全文经过 UTF-8 安全裁剪后不超过 128 KiB。
- 输入提示在全文与选区模式之间正确切换。
- 相关单元测试、站点测试、JavaScript 语法检查和 `mkdocs build --strict` 通过。
- 在实际 `mkdocs serve` 页面中确认聊天框无选区可发送，并且本地 AI 状态正常。
