# AI 聊天回答的 GFM 与公式渲染设计

## 目标

将 AI 阅读助手当前的轻量 Markdown 渲染器升级为完整、可维护且安全的 GFM 渲染链路。回答应正确显示标题、强调、删除线、链接、引用、任务列表、代码块、表格以及行内和块级数学公式，同时保持流式输出、移动端布局和本地运行边界不变。

## 方案

采用本地 vendored `marked` 解析 GFM，并使用本地 vendored `DOMPurify` 清洗解析结果。两个运行库不加入全局同步脚本列表，而是在首次需要渲染 AI 回答时按需加载；加载失败时回退到现有安全文本渲染，不影响博客与聊天主流程。

原始 HTML 即使由 Markdown 解析器接受，也必须经过 DOMPurify 白名单。禁止 `script`、事件属性、内联样式、iframe、表单和远程图片。链接只允许安全协议；外部链接统一补充 `target="_blank"` 和 `rel="noopener noreferrer"`。模型输出不得绕过清洗器直接写入 `innerHTML`。

## 数学公式

为 Markdown 解析器增加数学扩展，识别：

- 行内公式：`$...$` 与 `\(...\)`；
- 块级公式：`$$...$$` 与 `\[...\]`。

数学 token 输出为带 `.arithmatex` 的安全容器，并转换为博客现有 MathJax 配置使用的 `\(...\)` 或 `\[...\]` 分隔符。现有 `mathjax.js` 将提供可重复调用的页面级 typeset 入口：若运行时尚未加载则按需加载本地 MathJax，加载完成后只排版当前回答容器。

流式生成期间继续显示 Markdown 结构，但不反复执行 MathJax；收到完整 `done` 事件后再排版公式，避免不完整 TeX、重复 SVG 和明显闪烁。

## 表格与响应式布局

GFM 表格由 `marked` 生成语义化 `table`、`thead`、`tbody`。回答区为表格提供独立横向滚动容器或等效溢出规则，窄屏不撑破聊天抽屉。表头、边框、斑马纹、代码单元格和长公式沿用当前博客的青绿/暖橙视觉体系。

代码块和块级公式同样允许横向滚动；不得扩大聊天抽屉既有宽度，也不得改变移动端底部面板高度策略。

## 依赖与构建

`marked`、`DOMPurify` 必须固定明确版本并保存到本地 vendor 目录，同时记录许可证、来源版本和文件校验信息。生产页面继续加载压缩后的 AI 主脚本；源码与压缩产物保持同一 build marker。

按需依赖不计入首屏同步 JavaScript，但需要纳入本地资源、许可证与来源测试。运行时不访问 CDN。

## 错误处理

- Markdown 依赖加载失败：回退现有安全渲染器，并在控制台记录无敏感信息的类别；回答文本仍可阅读。
- MathJax 加载或排版失败：保留清洗后的 TeX 原文，不把整条回答标记为 AI 服务失败。
- 非法或危险 HTML：静默移除危险节点和属性，不执行任何脚本或远程资源。

## 验收

1. GFM 表格、强调、删除线、引用、任务列表、代码块和安全链接正确显示。
2. 四种公式分隔符均能通过本地 MathJax 排版，流式期间不会重复 typeset。
3. `script`、事件属性、`javascript:` 链接、iframe、表单和远程图片均不能生效。
4. 桌面和移动端表格、代码、公式不会撑破聊天面板。
5. 依赖完全本地化，许可证与来源可追溯；严格构建、相关测试和 JavaScript 预算检查通过。
6. AI 接口失败、Markdown 依赖失败或 MathJax 失败均不影响博客启动与基本阅读。
