# AI 阅读助手全文上下文回退设计（修订版）

> 本文取代 `whole-article-context-fallback-design-0825-1933.md`。检查实现后确认代理当前要求划线内容非空且正文不超过 10,000 字符，因此需要同步调整本地代理的请求校验和上游提示。

## 目标与交互

AI 阅读助手应当随时可以直接提问，不再强制用户先划线：

- 有有效选区时，显示“当前引用”，发送选中文字和相关正文块。
- 无选区时，不显示引用卡片，输入提示为“询问整篇文章…”，发送当前文章全文。
- 移除引用后回退到全文模式。
- 页面即时导航后，在提交时读取新页面正文，避免复用旧上下文。
- 空状态文案明确说明既可以直接提问，也可以划线聚焦。

## 客户端上下文解析

提交时调用统一解析逻辑：优先返回 `state.reference`；否则读取当前 `.md-content__inner`。全文模式从 `h1` 或页面标题取得标题，从文章容器取得可见纯文本，规范化空白并保留段落换行。文章容器缺失或正文为空时，不发送请求，保留问题输入并显示通用错误，同时只在本地控制台记录错误类别。

客户端保留 128 KiB 总请求上限，并按以下顺序缩减：

1. 移除最旧的历史消息。
2. 若仍超限，用二分法按 UTF-8 编码后的实际请求大小截短 `context`。
3. 保留当前问题、标题、路径和选区，不拆断 Unicode 码点。

常规文章会完整发送；只有超过请求预算的文章才会被截短。

## 本地代理兼容

- `selection` 从必填字符串改为可空字符串，仍限制在 4,000 字符内。
- `context` 仍为必填，但字符上限提高到 100,000；HTTP 层继续以 128 KiB `Content-Length` 作为最终边界。
- 上游提示区分两种模式：有选区时标记“划线引用”，无选区时标记“整篇文章”，避免把空选区误解为缺失数据。
- 系统提示改为优先依据“文章标题、正文上下文和可选划线原文”。

## 实现边界

不修改 API Key、模型、推理强度、代理端口、CORS 白名单或公网访问策略；不增加依赖，也不在页面加载时预先复制全文。

## 测试与验收

- 代理接受空 `selection` 和有效全文，继续拒绝空 `context` 及超限正文。
- 上游提示能区分整篇文章与划线引用。
- 前端无选区可构造全文请求，有选区继续优先引用，移除引用后回退全文。
- 超长中文正文经过 UTF-8 预算裁剪后不超过 128 KiB。
- 全文/选区输入提示正确切换。
- 相关测试、JavaScript 语法检查和 `mkdocs build --strict` 通过。
- 实际 `mkdocs serve` 页面中，无划线提问能获得流式回答。
