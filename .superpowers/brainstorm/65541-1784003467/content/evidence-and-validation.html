必须新增的 6 组原创图解
01 · 总闭环
数据 → 随机时间步加噪 → denoiser loss

随机噪声 → 重复 denoiser / scheduler → 样本
02 · 分布演化
二维 toy data 从多峰分布逐渐变成高斯，再沿学到的方向返回。
03 · DDPM 系数
把 x₀、噪声 ε、xₜ 与 signal/noise coefficient 放在一张图中。
04 · U-Net / DiT 接口
标出 noisy sample、timestep、condition 怎样进入网络，以及 prediction 怎样返回 sampler。
05 · Stable Diffusion
文本编码、latent 初始化、循环去噪、VAE 解码；训练流和推理流并排。
06 · 方法坐标系
DDPM、DDIM、Score/SDE、Flow、Consistency 分别改变训练目标、路径、求解器还是终点映射。

论文原图只在需要忠实说明原方法时使用；基础直觉优先用本站原创图，避免读者被论文符号和实验上下文淹没。

最小代码交付
  • 独立示例目录与固定依赖说明
  • 训练脚本、采样脚本、轻量 smoke test
  • 固定 seed 与预期输出图
  • 系数、shape、device 和范围断言
  • 正文代码片段从可运行脚本抽取，避免两份实现漂移
代码成功标准
  • q_sample(x0, t, noise) 输出形状与输入一致
  • t=0 接近干净样本，高时间步接近噪声
  • 单 batch 能前向、反向并更新参数
  • reverse loop 在固定 seed 下可复现
  • 短跑 smoke test 不承诺高画质，只验证链路完整

三层验收
A

读者验收

基础主线每篇 3–5 个自测；最终能画出训练/采样数据流、解释 loss、识别 Stable Diffusion 组件，并运行最小程序。

B

内容验收

检查术语首次定义、符号一致性、跨页重复、图源边界、公式—代码映射和站内前后置链接。

C

仓库验收

make quality、make image-quality、示例 smoke test、make build；最后人工浏览移动端目录、公式和图片。

实施顺序
  1. P0：先重写首页与导航，建立主线占位和文章职责。
  2. P1：完成 beginner primer 与 DDPM 数学页，让“扩散模型是什么”先真正成立。
  3. P2：完成架构/Stable Diffusion 与最小代码，打通理论到系统。
  4. P3：拆出 Flow 页面，清理旧文重复和站内链接。
  5. P4：补图、做全量质量检查与构建验证。
